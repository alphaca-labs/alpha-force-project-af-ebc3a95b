# 액터와 역할

> 이 파일의 역할: 시스템의 모든 역할과 인증·가입 정책을 정의한다. 역할별 접근 권한 매트릭스는 `07-api-and-permissions.md` 에 있다.

## 페르소나

페르소나는 이용 동기와 사용 맥락을 구분하기 위한 분류이며, 시스템 권한을 부여하거나 제한하는 기준으로 사용해서는 안 된다.

### 사회초년생

- 소득이 발생하기 시작했으나 부동산 매수 절차와 자금 계획 수립 경험이 부족한 2030 세대다.
- 희망 주택과 현재 자산의 격차, 예상 매입 가능 시점, 월별 저축 목표를 빠르게 파악해야 한다.
- 복잡한 금융 용어보다 게임형 시각화, 조건 변경에 따른 즉각적인 결과 비교, 실행 가능한 미션을 선호한다.
- 회원가입 없이 결과를 생성하고 이미지 또는 고유 URL로 저장·공유할 수 있어야 한다.

### 예비·신혼부부

- 결혼을 앞두었거나 신혼 생활 중이며, 부부의 자산과 소득을 합산하여 첫 주택 마련을 계획한다.
- 합산 소득, 보유 자산, 저축 여력과 우대 조건을 반영한 자금 조달 시나리오가 필요하다.
- 정부 지원 대출 및 청약 조건을 비교하고 공동으로 검토할 수 있는 실행 로드맵을 필요로 한다.
- 별도의 공동 계정을 만들지 않고 결과 이미지 또는 고유 URL을 상대방과 공유할 수 있어야 한다.

## 시스템 역할

| ID | 역할 | 설명 | 인증 필요 여부 |
|---|---|---|---|
| ROLE-비로그인 방문자 | 비로그인 방문자 | 고객용 웹에서 목표 매물과 재정 조건을 입력하고 시뮬레이션, 자금 조달 로드맵, 미션 체크리스트, 이미지 저장 및 고유 URL 공유 기능을 사용해야 한다. | 불필요 — 가입 및 로그인 없이 이용 |
| ROLE-운영자 | 운영자 | 별도 백오피스에서 부동산 매물 시세와 우대 대출 조건을 조회·등록·수정하고 운영 데이터를 관리해야 한다. | 필수 — 운영자 전용 인증 |
| ROLE-시스템 | 시스템 | 외부 데이터 수집, 시세 정규화, 대출 조건 매칭, 시나리오 연산, 결과 생성 등 사용자 또는 운영자가 직접 수행하지 않는 자동화 작업을 실행해야 한다. | 필수 — 비대화형 시스템 인증 |

- 역할명 `비로그인 방문자`, `운영자`, `시스템`은 `07-api-and-permissions.md`의 권한 매트릭스 축에서 동일한 문자열로 사용해야 한다.
- 하나의 요청에는 검증된 단일 역할만 적용해야 하며, 역할 간 권한을 암묵적으로 상속해서는 안 된다.

## 인증·가입 정책

- 고객용 서비스는 회원가입, 로그인, 소셜 로그인 및 고객 계정 기능을 제공해서는 안 된다.
- ROLE-비로그인 방문자는 신원 정보 제출 없이 모든 고객용 시뮬레이션 및 로드맵 기능을 이용할 수 있어야 한다.
- 비로그인 방문자의 체크리스트와 기기 저장 데이터는 해당 브라우저의 로컬 저장 영역에 보관해야 하며, 이를 사용자 계정으로 간주해서는 안 된다.
- 브라우저 데이터 삭제, 저장 차단 또는 기기 변경 시 로컬 저장 데이터가 복구되지 않을 수 있음을 저장 시점에 고지해야 한다.
- 공유용 고유 URL은 로그인 없이 열 수 있어야 하며, 추측이 불가능한 접근 토큰을 포함해야 한다. 유효한 URL을 보유한 사용자는 ROLE-비로그인 방문자로 공유 결과에 접근해야 한다.
- 공유 결과에는 시뮬레이션 재현과 공유 이미지 표시에 필요한 정보만 포함해야 하며, 외부 기관 조회를 위해 일시적으로 입력된 식별 정보나 인증 정보를 포함해서는 안 된다.
- ROLE-운영자는 고객용 화면과 분리된 백오피스 인증 절차를 거쳐야 한다.
- 운영자 인증은 검증된 이메일 주소와 비밀번호를 기본 자격 증명으로 사용하고, 추가 인증 수단을 반드시 요구해야 한다. 소셜 로그인은 제공해서는 안 된다.
- 운영자 비밀번호는 12자 이상이어야 하며, 이미 사용 중이거나 유출된 것으로 확인된 비밀번호를 허용해서는 안 된다.
- 운영자 인증 실패가 반복되면 추가 인증 또는 일시적 시도 제한을 적용해야 하며, 실패 여부로 계정 존재 유무가 노출되어서는 안 된다.
- 운영자 세션은 30분 동안 활동이 없으면 만료되어야 하며, 인증 후 12시간이 지나면 활동 여부와 관계없이 재인증을 요구해야 한다.
- 운영자 로그아웃, 계정 비활성화, 비밀번호 변경 또는 추가 인증 수단 재설정 시 기존 세션을 모두 무효화해야 한다.
- 운영자 비밀번호 재설정은 검증된 운영자 이메일로 전달되는 일회성·만료형 링크를 통해서만 수행해야 한다.
- ROLE-시스템은 사람용 로그인 화면을 사용해서는 안 되며, 실행 주체별로 분리되고 교체 가능한 시스템 자격 증명으로 인증해야 한다.
- 역할 판정과 운영자 인증 상태는 신뢰할 수 있는 서버 측 정보로 결정해야 하며, 클라이언트가 전달한 역할명이나 화면 상태를 권한 근거로 사용해서는 안 된다.

## 운영자 계정 발급 및 수명주기

- 최초 ROLE-운영자 계정은 배포 시 보안 입력값을 사용한 시드 방식으로 한 번만 생성해야 한다.
- 최초 운영자 계정의 이메일과 초기 자격 증명을 소스 코드, 배포 산출물 또는 기본 설정값에 포함해서는 안 된다.
- 최초 로그인 시 운영자는 초기 비밀번호를 변경하고 추가 인증 수단을 등록해야 하며, 완료 전에는 백오피스 관리 기능에 접근할 수 없어야 한다.
- 추가 운영자 계정은 인증된 ROLE-운영자가 이메일 초대를 발급하는 방식으로만 생성해야 한다. 공개 가입과 임의의 역할 신청은 허용해서는 안 된다.
- 운영자 초대 링크는 지정된 이메일에 귀속된 일회성 토큰이어야 하며, 발급 후 24시간이 지나면 만료되어야 한다.
- 초대 수락 시 이메일 검증, 비밀번호 설정 및 추가 인증 수단 등록을 모두 완료해야 계정을 활성화해야 한다.
- 만료되거나 사용된 초대는 재사용할 수 없어야 하며, 필요한 경우 새 초대를 발급해야 한다.
- 운영자는 다른 운영자 계정을 비활성화할 수 있어야 한다. 비활성화 즉시 해당 계정의 모든 세션과 미사용 초대를 무효화해야 한다.
- 마지막 활성 운영자 계정은 비활성화할 수 없어야 한다.
- 운영자 계정 생성, 초대, 초대 취소, 인증 성공·실패, 비밀번호 재설정, 추가 인증 수단 변경, 비활성화 및 재활성화 행위를 감사 기록으로 남겨야 한다.

## 수락 시나리오

### 비로그인 이용

- **Given** 사용자가 인증 정보 없이 고객용 웹에 접속했고
- **When** 목표 매물과 재정 조건을 입력하여 시뮬레이션을 실행하면
- **Then** 시스템은 회원가입이나 로그인을 요구하지 않고 ROLE-비로그인 방문자 권한으로 결과와 로드맵을 제공해야 한다.

### 공유 URL 접근

- **Given** 유효한 공유용 고유 URL이 생성되었고
- **When** 로그인하지 않은 사용자가 해당 URL을 열면
- **Then** 시스템은 ROLE-비로그인 방문자로 공유 결과를 표시하고 운영자 기능을 노출해서는 안 된다.

### 운영자 초대 활성화

- **Given** 활성 운영자가 24시간 이내의 미사용 초대를 발급했고
- **When** 초대받은 사용자가 지정된 이메일 검증, 비밀번호 설정 및 추가 인증 수단 등록을 완료하면
- **Then** 시스템은 ROLE-운영자 계정을 활성화하고 백오피스 접근을 허용해야 한다.

### 운영자 세션 무효화

- **Given** 운영자가 하나 이상의 활성 세션을 보유하고 있고
- **When** 해당 계정이 비활성화되거나 비밀번호 또는 추가 인증 수단이 변경되면
- **Then** 시스템은 기존 세션을 모두 무효화하고 다음 요청부터 재인증 또는 접근 거부를 적용해야 한다.

### 역할 위조 차단

- **Given** 비로그인 요청이 클라이언트 입력에 `운영자` 역할명을 포함했고
- **When** 백오피스 기능에 접근하면
- **Then** 시스템은 해당 역할명을 무시하고 유효한 운영자 인증이 없으므로 접근을 거부해야 한다.
