# 기능 요구사항

> 이 파일의 역할: 도메인별 유저스토리·수락기준·엣지케이스·기능 요구를 전량 정의한다. 이 파일의 FR-### 이 구현 범위의 기준이다.

## 목표 설정 및 자산 분석

목표 매물·평형과 재정 조건을 검증된 시세에 연결하여 시뮬레이션 입력 상태를 구성한다.

**FR-001** 비로그인 방문자로서 대표 랜드마크 매물을 바로 선택하고 싶다, 매물명을 직접 입력하지 않고 시뮬레이션을 시작하기 위해.
- FR-001.AC1: Given 목표 매물 설정 화면, When 검색창을 선택하면, Then 추천 상태인 대표 아파트·오피스텔이 운영자가 지정한 노출 순서대로 최대 8개 표시된다.
- FR-001.AC2: Given 추천 키워드 목록, When 키워드를 선택하면, Then 해당 매물이 검색 입력란에 반영되고 평형 선택 단계가 열린다.
- Edge: 추천 매물이 비활성화되거나 유효한 평형을 보유하지 않음 — 추천 목록에서 즉시 제외한다.
- 규칙: 시스템은 반포자이와 은마아파트를 포함하여 운영자가 활성화한 추천 매물만 노출해야 한다(MUST).

**FR-002** 비로그인 방문자로서 전국 아파트와 오피스텔을 명칭으로 검색하고 싶다, 원하는 목표 매물을 정확히 선택하기 위해.
- FR-002.AC1: Given 매물 검색 입력란, When 두 글자 이상의 검색어를 입력하면, Then 명칭·도로명 주소·주택 유형이 일치하는 활성 매물을 관련도순으로 최대 20개 표시한다.
- FR-002.AC2: Given 검색 결과, When 매물을 선택하면, Then 동일 명칭 매물을 구분할 수 있도록 주소와 주택 유형을 포함한 선택 상태가 표시된다.
- FR-002.AC3: Given 검색 결과가 없음, When 검색이 완료되면, Then 데이터 없음 안내·검색어 수정 수단·추천 키워드를 표시한다.
- Edge: 앞뒤 공백·연속 공백·영문 대소문자 차이 — 정규화한 검색어로 동일하게 조회한다.
- Edge: 동명 매물이 여러 지역에 존재함 — 하나로 합치지 않고 주소별 항목으로 표시한다.
- 규칙: 시스템은 아파트와 오피스텔 이외의 주택 유형을 검색 결과에 포함해서는 안 된다(MUST).

**FR-003** 비로그인 방문자로서 선택한 매물의 평형을 지정하고 싶다, 실제로 원하는 주택 규모의 시세를 목표로 사용하기 위해.
- FR-003.AC1: Given 활성 매물 선택, When 평형 목록을 열면, Then 전용면적㎡·환산 평수·시세 기준일이 포함된 평형 목록이 면적 오름차순으로 표시된다.
- FR-003.AC2: Given 유효한 시세가 연결된 평형, When 하나를 선택하면, Then 매물·평형·정규화 시세가 목표 설정 완료 상태로 연결된다.
- FR-003.AC3: Given 유효한 시세가 없는 평형, When 해당 평형을 선택하면, Then 시세 확인 불가 상태와 다른 평형 또는 매물 선택 수단이 표시되고 다음 단계 진행이 차단된다.
- Edge: 동일 평형에 복수의 전용면적이 존재함 — 전용면적별로 별도 선택 항목을 제공한다.
- 규칙: 시스템은 유효한 실거래가나 운영자 확정 시세가 없는 평형에 임의 가격을 생성해서는 안 된다(MUST).

**FR-004** 비로그인 방문자로서 현재 재정 조건을 입력하고 싶다, 내 상황에 맞는 자금 격차와 달성 기간을 계산하기 위해.
- FR-004.AC1: Given 유효한 목표 매물·평형 선택, When 재정 조건 화면을 열면, Then 현재 보유 자산·연 소득·월 저축 가능 금액·보유 대출 잔액·연간 원리금 상환액 입력란이 표시된다.
- FR-004.AC2: Given 부부 합산 조건을 사용하는 방문자, When 합산 금액을 입력하면, Then 시스템은 이를 하나의 가구 재정 조건으로 계산한다.
- FR-004.AC3: Given 유효한 필수 입력값, When 시뮬레이션 실행을 선택하면, Then 입력값이 원 단위 정수로 정규화되어 현재 시뮬레이션에 반영된다.
- Edge: 보유 대출이 없음 — 대출 잔액과 연간 원리금 상환액을 0으로 입력할 수 있다.
- 규칙: 시스템은 성명·주민등록번호·금융기관 인증 정보 입력을 요구해서는 안 된다(MUST).

**FR-005** 비로그인 방문자로서 잘못된 재정 입력을 즉시 확인하고 싶다, 왜곡된 결과 생성을 방지하기 위해.
- FR-005.AC1: Given 재정 조건 입력, When 음수·숫자가 아닌 값·소수 원 단위·999,999,999,999원을 초과한 값을 제출하면, Then 해당 필드에 오류 사유가 표시되고 실행이 차단된다.
- FR-005.AC2: Given 연 소득이 0원이거나 월 저축 가능 금액이 0원인 입력, When 제출하면, Then 값은 허용되며 대출 한도 또는 목표 기간을 산출할 수 없는 사유가 결과에 표시된다.
- Edge: 쉼표나 원화 기호가 포함됨 — 표시 문자를 제거한 뒤 원 단위 정수로 검증한다.
- Edge: 연간 원리금 상환액이 연 소득을 초과함 — 입력은 유지하되 DSR 기반 추가 대출 가능액을 0원으로 처리한다.
- 규칙: 시스템은 오류가 있는 필드에 초점을 이동할 수 있는 오류 요약과 필드별 메시지를 제공해야 한다(MUST).

## 매매 및 유머 시뮬레이션

정규화 시세와 재정·대출 조건을 동일한 기준 시점으로 계산하고 게임 스테이터스와 우회 시나리오로 표현한다.

**FR-006** 시스템으로서 실거래 데이터를 평형별 대표 시세로 정규화하고 싶다, 일관된 목표 가격을 제공하기 위해.
- FR-006.AC1: Given 취소되지 않은 실거래 데이터, When 평형 시세를 산출하면, Then 최근 거래일 기준 6개월 이내 동일 매물·동일 전용면적 거래의 중위가격을 대표 시세로 사용한다.
- FR-006.AC2: Given 6개월 내 거래가 없음, When 시세를 산출하면, Then 조회 범위를 12개월로 확장하고 거래가 한 건 이상이면 해당 기간 중위가격을 사용한다.
- FR-006.AC3: Given 유효기간 내 운영자 확정 시세, When 대표 시세를 조회하면, Then 자동 정규화 시세보다 운영자 확정 시세를 우선 적용하고 출처를 구분해 표시한다.
- Edge: 거래 취소 또는 정정 데이터 수신 — 기존 원거래를 대표 시세 계산에서 제외하고 재산출한다.
- Edge: 12개월 내 거래가 없음 — 시세 상태를 확인 불가로 변경한다.
- 규칙: 시스템은 대표 시세에 기준일·산정 대상 거래 기간·데이터 출처를 연결해야 한다(MUST).

**FR-007** 비로그인 방문자로서 목표 주택 대비 현재 자금 격차를 보고 싶다, 매입 가능 수준을 즉시 판단하기 위해.
- FR-007.AC1: Given 유효한 목표 시세와 재정 조건, When 시뮬레이션이 실행되면, Then 목표 시세·보유 자산·예상 대출 한도·부족 자금·목표 달성률이 원 단위 계산 결과로 표시된다.
- FR-007.AC2: Given 계산 결과, When 부족 자금을 산출하면, Then `max(목표 시세 - 보유 자산 - 예상 대출 한도, 0)`이 적용된다.
- FR-007.AC3: Given 계산 결과, When 목표 달성률을 산출하면, Then `min((보유 자산 + 예상 대출 한도) ÷ 목표 시세 × 100, 100)`이 소수점 첫째 자리까지 표시된다.
- Edge: 보유 자산이 목표 시세 이상임 — 부족 자금은 0원, 목표 달성률은 100%로 표시한다.
- 규칙: 시스템은 취득세·중개보수·이사비 등 부대비용이 결과에 포함되지 않았음을 계산 상세에 표시해야 한다(MUST).

**FR-008** 비로그인 방문자로서 LTV와 DSR을 반영한 예상 대출 한도를 알고 싶다, 현실적인 조달 가능액을 계산하기 위해.
- FR-008.AC1: Given 적용 가능한 대출 조건, When 한도를 산출하면, Then 담보가치×LTV 한도·DSR 잔여 상환 여력의 원금 환산 한도·상품별 최대 한도 중 최솟값을 상품 예상 한도로 사용한다.
- FR-008.AC2: Given 기존 연간 원리금 상환액, When DSR 한도를 계산하면, Then 허용 연간 상환액에서 기존 연간 원리금 상환액을 차감한 잔여액만 신규 대출 상환 여력으로 사용한다.
- FR-008.AC3: Given 복수의 적격 상품, When 총 예상 대출 한도를 선택하면, Then 중복 실행할 수 없는 상품은 가장 큰 단일 한도만 사용하고 병행 가능한 상품만 중복 없이 합산한다.
- Edge: DSR 잔여 상환 여력이 0원 이하임 — DSR 기반 신규 한도를 0원으로 처리한다.
- Edge: 적용 가능한 대출 조건이 없음 — 예상 대출 한도를 0원으로 표시하고 사유를 제공한다.
- 규칙: 시스템은 계산에 사용한 LTV·DSR·금리·상환기간·상품 한도와 기준일을 상세 결과에 표시해야 한다(MUST).

**FR-009** 비로그인 방문자로서 현재 저축 속도로 필요한 기간을 보고 싶다, 현실적인 목표 달성 시점을 판단하기 위해.
- FR-009.AC1: Given 부족 자금이 0원보다 크고 월 저축 가능 금액이 0원보다 큼, When 기간을 계산하면, Then `ceil(부족 자금 ÷ 월 저축 가능 금액)`을 필요 개월 수로 표시하고 연·개월로 변환한다.
- FR-009.AC2: Given 부족 자금이 0원, When 결과가 표시되면, Then 예상 기간을 즉시 가능으로 표시한다.
- FR-009.AC3: Given 부족 자금이 존재하고 월 저축 가능 금액이 0원, When 결과가 표시되면, Then 기간 계산 불가와 필요한 조건 변경을 표시한다.
- Edge: 계산 기간이 1,200개월 이상임 — 숫자 전체 대신 `100년 이상`으로 표시하되 원 계산값은 캐릭터 판정에 유지한다.
- 규칙: 시스템은 미래 집값 상승·저축 이자·투자 수익을 기본 기간 계산에 반영해서는 안 된다(MUST).

**FR-010** 비로그인 방문자로서 계산 결과를 캐릭터 상태로 보고 싶다, 목표 난이도를 직관적으로 이해하기 위해.
- FR-010.AC1: Given 예상 기간이 즉시 가능 또는 12개월 이하임, When 결과가 표시되면, Then 선글라스를 끼고 꺼드럭거리는 픽셀 캐릭터와 여유 상태를 표시한다.
- FR-010.AC2: Given 예상 기간이 12개월 초과 1,200개월 미만임, When 결과가 표시되면, Then 천장의 굴비를 바라보며 흰쌀밥을 먹는 자린고비 픽셀 캐릭터와 영끌 노력 상태를 표시한다.
- FR-010.AC3: Given 예상 기간이 1,200개월 이상이거나 계산 불가임, When 결과가 표시되면, Then 퀭한 눈으로 담배를 피우는 픽셀 캐릭터와 이번 생 불가 상태를 표시한다.
- Edge: 경계값이 정확히 12개월 또는 1,200개월임 — 각각 여유 상태와 이번 생 불가 상태를 적용한다.
- 규칙: 시스템은 동일한 계산 입력에 항상 동일한 캐릭터 상태를 반환해야 한다(MUST).

**FR-011** 비로그인 방문자로서 내 결과를 게임 스테이터스 형태로 보고 싶다, 주요 수치를 한 화면에서 이해하고 공유하기 위해.
- FR-011.AC1: Given 완료된 시뮬레이션, When 결과 피드백 화면을 열면, Then 캐릭터·절망 지수·보유 자산 스펙·생존 연한 능력치 그래프·장착 장비·레이드 시스템 메시지가 표시된다.
- FR-011.AC2: Given 예상 기간이 계산 가능함, When 절망 지수를 산출하면, Then `min(ceil(예상 개월 수 ÷ 12), 100)`을 0~100 값으로 표시하며 즉시 가능은 0으로 표시한다.
- FR-011.AC3: Given 결과 상태가 결정됨, When 장착 장비와 시스템 메시지를 생성하면, Then 상태별 사전 정의 문구 집합에서 목표 매물명·평형·기간을 결합해 표시한다.
- Edge: 매물명이 표시 영역을 초과함 — 의미를 보존해 말줄임하고 전체 명칭을 별도로 확인할 수 있게 한다.
- 규칙: 시스템은 재정 계산값과 유머 문구를 시각적으로 구분하고 유머 문구를 금융 조언으로 표현해서는 안 된다(MUST).

**FR-012** 비로그인 방문자로서 모든 막장 우회 시뮬레이션을 비교하고 싶다, 기본 저축 외 대안의 비현실성을 수치로 즐기기 위해.
- FR-012.AC1: Given 완료된 시뮬레이션, When 결과 화면을 아래로 이동하면, Then 로또·코인·대기업 노예·인생 리셋 카드가 누락 없이 한 페이지에 표시된다.
- FR-012.AC2: Given 우회 카드 표시, When 상세를 열면, Then 로또는 필요한 실수령 당첨 총액, 코인은 현재 보유 자산 대비 필요한 수익 배수와 수익률, 대기업 노예는 10년 내 충당에 필요한 연간 추가 저축액, 인생 리셋은 다음 생 시작 시 필요한 초기 자산을 표시한다.
- FR-012.AC3: Given 입력 조건이 변경됨, When 재계산이 완료되면, Then 네 우회 카드의 수치와 설명이 같은 부족 자금을 기준으로 함께 갱신된다.
- Edge: 현재 보유 자산이 0원임 — 코인 수익 배수를 계산 불가로 표시하고 필요한 시작 원금을 부족 자금과 함께 안내한다.
- Edge: 부족 자금이 0원임 — 모든 우회 카드를 불필요 상태로 표시하되 카드를 숨기지 않는다.
- 규칙: 시스템은 각 우회 카드에 풍자 목적이며 실제 수익·취업·당첨 가능성을 보장하지 않는다는 문구를 표시해야 한다(MUST).

**FR-013** 비로그인 방문자로서 결과 화면에서 조건을 조절하고 싶다, 여러 목표와 저축 전략을 빠르게 비교하기 위해.
- FR-013.AC1: Given 시뮬레이션 결과 화면, When 연 소득·월 저축 가능 금액 슬라이더를 조절하면, Then 대출 한도·부족 자금·예상 기간·달성률·캐릭터·우회 시나리오가 변경된 값으로 갱신된다.
- FR-013.AC2: Given 동일 매물의 평형 선택기, When 다른 유효 평형을 선택하면, Then 해당 평형 시세를 기준으로 전체 결과와 로드맵이 다시 계산된다.
- FR-013.AC3: Given 조절 중인 슬라이더, When 값이 변경되면, Then 현재 값은 즉시 표시되고 최종 입력 후 500밀리초 이내에 계산 요청이 시작된다.
- Edge: 변경한 평형의 시세가 더 이상 유효하지 않음 — 기존 결과를 덮어쓰지 않고 시세 확인 불가 상태와 재선택 수단을 표시한다.
- 규칙: 시스템은 재계산 전후 입력값과 시세 기준을 혼합한 결과를 표시해서는 안 된다(MUST).

**FR-014** 비로그인 방문자로서 시뮬레이션의 한계를 확인하고 싶다, 실제 금융 의사결정과 추정 결과를 구분하기 위해.
- FR-014.AC1: Given 대시보드 또는 로드맵 결과, When 결과가 표시되면, Then 실거래가·규제·금리 변동으로 실제 매입가와 대출 한도가 달라질 수 있다는 고지가 함께 표시된다.
- FR-014.AC2: Given 예상 대출 상품 또는 우대 조건, When 상세를 열면, Then 데이터 기준일과 실제 기관 심사가 필요하다는 안내가 표시된다.
- Edge: 적용 데이터 기준일이 현재 날짜보다 30일 이상 이전임 — 오래된 데이터 경고를 결과 상단에 표시한다.
- 규칙: 시스템은 추정 결과를 승인 확정·대출 가능 보장·매입 가능 보장으로 표현해서는 안 된다(MUST).

## 자금 조달 로드맵

가구 조건에 맞는 일반·정부 지원 대출과 청약 우대 조건을 판정하고 실행 가능한 조달 순서와 기간을 제시한다.

**FR-015** 비로그인 방문자로서 우대 조건 판정에 필요한 가구 정보를 선택적으로 입력하고 싶다, 더 정확한 상품 매칭을 받기 위해.
- FR-015.AC1: Given 로드맵 진입, When 자격 조건 입력을 열면, Then 무주택 여부·생애최초 여부·혼인 상태·혼인 기간·가구원 수·부양가족 수·연령을 입력할 수 있다.
- FR-015.AC2: Given 일부 자격 정보를 입력하지 않음, When 매칭을 실행하면, Then 해당 항목을 요구하는 상품은 확인 필요로 분류되고 누락 항목이 표시된다.
- Edge: 혼인 상태가 미혼임 — 혼인 기간 입력을 비활성화하고 기존 값을 계산에서 제거한다.
- 규칙: 시스템은 자격 판정을 위해 개인 식별번호나 증빙 파일을 수집해서는 안 된다(MUST).

**FR-016** 비로그인 방문자로서 청약과 정부 지원 대출의 우대 조건을 매칭하고 싶다, 적용 가능성이 높은 제도를 비교하기 위해.
- FR-016.AC1: Given 재정·가구 조건과 유효한 상품 규칙, When 매칭을 실행하면, Then 각 상품을 적격·부적격·확인 필요 중 하나로 분류하고 판정 근거를 조건별로 표시한다.
- FR-016.AC2: Given 디딤돌대출 또는 보금자리론 규칙이 유효함, When 방문자 조건과 일치하면, Then 예상 한도·금리 범위·상환기간·충족 우대 조건·미충족 조건을 표시한다.
- FR-016.AC3: Given 청약 우대 규칙, When 조건을 판정하면, Then 신청 가능성 판정과 함께 필요한 준비 항목 및 공식 확인 출처를 표시한다.
- Edge: 규칙 유효기간이 종료됨 — 매칭 대상에서 제외하고 종료된 조건으로 계산하지 않는다.
- 규칙: 시스템은 입력되지 않은 자격 정보를 임의로 적격으로 가정해서는 안 된다(MUST).

**FR-017** 비로그인 방문자로서 가장 현실적인 자금 조달 시나리오를 보고 싶다, 여러 대출 조합 중 실행 경로를 선택하기 위해.
- FR-017.AC1: Given 하나 이상의 적격 또는 확인 필요 상품, When 조달 시나리오를 생성하면, Then 보유 자산·상품별 예상 대출액·잔여 부족 자금·월 저축액·예상 달성 기간을 조합별로 표시한다.
- FR-017.AC2: Given 복수의 실행 가능한 조합, When 추천 조합을 선정하면, Then 예상 달성 기간이 짧은 조합, 연간 원리금 부담이 낮은 조합, 적용 금리가 낮은 조합 순으로 비교하여 하나를 추천한다.
- FR-017.AC3: Given 모든 상품이 부적격임, When 로드맵을 표시하면, Then 대출 0원 기준 저축 시나리오와 부적격 사유를 제공한다.
- Edge: 두 조합의 비교 기준이 모두 같음 — 상품명 오름차순으로 결과 순서를 고정한다.
- 규칙: 시스템은 상호 배타적인 상품을 하나의 조달 조합에 포함해서는 안 된다(MUST).

**FR-018** 비로그인 방문자로서 목표 달성까지의 단계별 로드맵을 보고 싶다, 무엇을 언제 준비할지 알기 위해.
- FR-018.AC1: Given 추천 조달 시나리오, When 로드맵 상세를 열면, Then 현재 상태·자산 축적·자격 확인·대출 준비·매입 준비 순서의 단계와 예상 달성 기간이 표시된다.
- FR-018.AC2: Given 월 저축 가능 금액이 0원보다 큼, When 저축 미션을 생성하면, Then 월간 목표는 입력된 월 저축액, 주간 목표는 `floor(월 저축액 × 12 ÷ 52)`로 설정된다.
- FR-018.AC3: Given 매칭된 상품에 필수 준비 조건이 있음, When 미션을 생성하면, Then 조건 확인·서류 준비·공식 기관 재확인 항목이 해당 단계에 포함된다.
- Edge: 예상 기간이 계산 불가임 — 날짜 기반 단계를 생성하지 않고 조건 변경 미션을 첫 단계로 제공한다.
- 규칙: 시스템은 로드맵 미션마다 주간·월간 구분, 완료 기준 및 관련 조달 시나리오를 연결해야 한다(MUST).

## 실행 가이드 및 공유 관리

로드맵 실천 상태를 브라우저에 저장하고 현재 결과를 게임 이미지와 접근 토큰 기반 URL로 공유한다.

**FR-019** 비로그인 방문자로서 주간·월간 미션의 완료 상태를 변경하고 싶다, 실행 현황을 지속해서 관리하기 위해.
- FR-019.AC1: Given 실행 체크리스트, When 미션의 완료 여부를 변경하면, Then 변경 상태와 변경 시각이 해당 브라우저의 로컬 저장 영역에 즉시 저장된다.
- FR-019.AC2: Given 일부 미션 완료, When 체크리스트를 확인하면, Then 전체·주간·월간 완료 수와 완료율이 표시된다.
- Edge: 로드맵 재계산으로 동일 미션이 유지됨 — 미션 식별자가 같은 항목의 완료 상태를 보존한다.
- Edge: 미션이 새 로드맵에서 제거됨 — 화면에서는 제외하되 다른 미션의 상태를 초기화하지 않는다.
- 규칙: 시스템은 체크리스트 완료 상태를 사용자 계정 데이터로 취급하거나 서버 계정과 동기화해서는 안 된다(MUST).

**FR-020** 비로그인 방문자로서 같은 브라우저에서 체크리스트를 복원하고 싶다, 로그인 없이 이전 실행 상태를 이어가기 위해.
- FR-020.AC1: Given 로컬 저장된 체크 상태, When 같은 브라우저로 동일 체크리스트를 다시 열면, Then 저장된 완료 상태가 자동 복원된다.
- FR-020.AC2: Given 해당 브라우저의 첫 체크 상태 저장, When 저장이 완료되면, Then 브라우저 데이터 삭제·저장 차단·기기 변경 시 복구할 수 없다는 고지가 한 번 표시된다.
- FR-020.AC3: Given 로컬 저장이 차단됨, When 상태 변경을 시도하면, Then 화면 내 임시 상태는 유지되고 재방문 시 복원되지 않는다는 오류를 표시한다.
- Edge: 저장 데이터가 손상됨 — 손상된 항목만 초기화하고 체크리스트를 계속 사용할 수 있게 한다.
- 규칙: 시스템은 로컬 저장 실패를 체크리스트 열람 차단 사유로 사용해서는 안 된다(MUST).

**FR-021** 비로그인 방문자로서 현재 결과를 인생 스펙 이미지로 저장하고 싶다, 기기에 소장하거나 소셜 미디어에 게시하기 위해.
- FR-021.AC1: Given 완료된 현재 시뮬레이션, When 이미지 저장을 선택하면, Then 1080×1350 세로형 이미지 미리보기가 생성된다.
- FR-021.AC2: Given 이미지 생성 완료, When 저장을 확정하면, Then 픽셀 캐릭터·목표 매물과 평형·목표 달성률·절망 지수·보유 자산 스펙·생존 연한 그래프·장착 장비·레이드 시스템 메시지가 포함된 PNG 파일을 기기에 저장할 수 있다.
- FR-021.AC3: Given 이미지 미리보기, When 저장 전 확인하면, Then 이미지에 포함될 재정 수치와 공개 공유 주의 문구가 표시된다.
- Edge: 긴 매물명 또는 큰 금액이 레이아웃을 초과함 — 단위를 축약하되 원래 의미와 통화 단위를 유지한다.
- Edge: 이미지 생성 실패 — 현재 결과를 유지하고 재시도 수단을 제공한다.
- 규칙: 시스템은 외부 기관 조회용 식별 정보·인증 정보·보유 대출의 금융기관 식별값을 이미지에 포함해서는 안 된다(MUST).

**FR-022** 비로그인 방문자로서 결과를 고유 URL로 공유하고 싶다, 상대방이 로그인 없이 동일한 결과를 확인하게 하기 위해.
- FR-022.AC1: Given 완료된 시뮬레이션, When 공유 URL 생성을 확정하면, Then 추측 불가능한 접근 토큰이 포함된 고유 URL이 생성된다.
- FR-022.AC2: Given 공유 생성 확인 화면, When 방문자가 공개 항목을 검토하면, Then 목표 매물·평형·재정 요약·시나리오 결과·로드맵 요약이 링크 보유자에게 공개됨을 명시한다.
- FR-022.AC3: Given 동일 결과에서 공유를 다시 선택, When 기존 URL 재사용을 선택하면, Then 결과가 변경되지 않은 경우 기존 URL을 반환하고 결과가 변경된 경우 새 URL을 생성한다.
- Edge: 공유 결과 저장 중 오류 — 불완전한 URL을 반환하지 않고 재시도 수단을 제공한다.
- 규칙: 시스템은 공유 결과에 외부 기관 조회를 위해 일시 입력된 식별 정보나 인증 정보를 포함해서는 안 된다(MUST).

**FR-023** 비로그인 방문자로서 인스타그램과 스레드에 결과를 전달하고 싶다, 생성한 이미지와 URL을 간편하게 게시하기 위해.
- FR-023.AC1: Given 생성된 이미지와 공유 URL, When 인스타그램 또는 스레드 공유를 선택하면, Then 지원되는 기기에서는 해당 공유 인터페이스에 이미지·URL·서비스명이 전달된다.
- FR-023.AC2: Given 브라우저가 이미지 직접 전달을 지원하지 않음, When 공유를 선택하면, Then 이미지 저장과 URL 복사 수단을 함께 제공하고 수동 게시 방법을 안내한다.
- Edge: 소셜 앱이 설치되지 않음 — 운영체제의 일반 공유 인터페이스 또는 URL 복사 대체 수단을 제공한다.
- 규칙: 시스템은 소셜 채널 공유 완료 여부를 확인할 수 없는 환경에서 완료된 것으로 표시해서는 안 된다(MUST).

**FR-024** 비로그인 방문자로서 공유받은 결과를 로그인 없이 열고 싶다, 상대방의 시뮬레이션을 즉시 검토하기 위해.
- FR-024.AC1: Given 유효한 공유 URL, When 로그인하지 않은 방문자가 열면, Then 저장된 입력 기준의 결과 이미지·대시보드·우회 시나리오·로드맵 요약이 읽기 전용으로 표시된다.
- FR-024.AC2: Given 공유 결과 화면, When 내 조건으로 다시 계산을 선택하면, Then 공유 결과를 원본으로 변경하지 않고 별도의 신규 시뮬레이션 입력 상태를 생성한다.
- FR-024.AC3: Given 유효하지 않거나 존재하지 않는 토큰, When URL을 열면, Then 결과 데이터를 노출하지 않고 링크 확인 불가 상태와 새 시뮬레이션 시작 수단을 표시한다.
- Edge: 공유 생성 후 원본 시세나 대출 규칙이 변경됨 — 공유 화면은 생성 당시 결과와 기준일을 유지한다.
- 규칙: 시스템은 공유 URL 보유자를 ROLE-비로그인 방문자로 처리하고 백오피스 기능을 노출해서는 안 된다(MUST).

## 운영 데이터 수집 및 백오피스 관리

외부 실거래 데이터와 운영자가 확정한 시세·대출 규칙을 검증·이력화하여 이후 시뮬레이션에 적용한다.

**FR-025** 시스템으로서 국토교통부 실거래가 데이터를 정기적으로 수집하고 싶다, 전국 아파트·오피스텔 시세를 최신 상태로 유지하기 위해.
- FR-025.AC1: Given 유효한 시스템 인증, When 수집 작업이 실행되면, Then 아파트·오피스텔의 매물 식별 정보·전용면적·거래금액·계약일·취소 여부를 증분 수집한다.
- FR-025.AC2: Given 동일 거래가 다시 수신됨, When 저장하면, Then 중복 거래를 생성하지 않고 정정·취소 상태만 갱신한다.
- FR-025.AC3: Given 수집 완료, When 작업 결과를 기록하면, Then 처리·신규·정정·실패 건수와 수집 기준 시각이 남는다.
- Edge: 외부 연동이 일시 실패함 — 기존 유효 데이터를 유지하고 실패 구간부터 재시도할 수 있게 한다.
- 규칙: 시스템은 수집 실패를 이유로 기존 정상 시세를 삭제하거나 0원으로 대체해서는 안 된다(MUST).

**FR-026** 운영자로서 매물과 평형별 시세를 검색하고 검증하고 싶다, 고객 시뮬레이션에 사용되는 목표 가격을 관리하기 위해.
- FR-026.AC1: Given 유효한 운영자 세션, When 매물 시세 관리 화면을 열면, Then 명칭·주소·주택 유형·평형·시세 상태·기준일로 검색 및 필터링할 수 있다.
- FR-026.AC2: Given 특정 평형 상세, When 열람하면, Then 원 실거래 목록·자동 정규화 시세·운영자 확정 시세·현재 적용값을 구분해 표시한다.
- Edge: 외부 원거래가 취소됨 — 취소 상태와 재산출 결과를 상세 화면에 표시한다.
- 규칙: 시스템은 운영자에게 원거래와 운영자 입력값의 출처를 혼동 없이 표시해야 한다(MUST).

**FR-027** 운영자로서 매물·평형의 적용 시세와 추천 노출 상태를 변경하고 싶다, 오류를 보정하고 대표 매물을 관리하기 위해.
- FR-027.AC1: Given 매물 또는 평형 편집 화면, When 명칭·주소·주택 유형·전용면적·확정 시세·유효기간·추천 여부·추천 순서를 저장하면, Then 검증된 값이 적용 상태와 함께 반영된다.
- FR-027.AC2: Given 운영자 확정 시세 저장, When 적용 시작일이 도래하면, Then 이후 시작되는 시뮬레이션은 해당 시세를 우선 사용한다.
- FR-027.AC3: Given 매물 또는 평형 비활성화, When 저장하면, Then 신규 검색·추천·목표 선택에서는 제외되고 기존 공유 결과는 유지된다.
- Edge: 확정 시세가 0원 이하이거나 유효기간 종료가 시작보다 빠름 — 저장을 차단하고 오류 필드를 표시한다.
- 규칙: 시스템은 적용 이력이 존재하는 매물·평형·시세를 물리적으로 삭제하지 않고 비활성화해야 한다(MUST).

**FR-028** 운영자로서 일반·정부 지원 대출과 청약 우대 조건을 관리하고 싶다, 최신 규제를 시뮬레이션에 반영하기 위해.
- FR-028.AC1: Given 대출 조건 편집 화면, When 상품명·유형·자격식·LTV·DSR·금리 범위·상환기간·최대 한도·병행 가능 여부·유효기간·공식 출처를 저장하면, Then 문법과 값 범위가 검증된 규칙 버전이 생성된다.
- FR-028.AC2: Given 청약 우대 조건 편집 화면, When 자격 조건·우대 내용·필요 준비 항목·유효기간·공식 출처를 저장하면, Then 이후 매칭에 적용 가능한 규칙 버전이 생성된다.
- FR-028.AC3: Given 미래 적용 규칙, When 적용 시작 시각 전후로 시뮬레이션을 실행하면, Then 시작 전에는 기존 규칙을, 시작 시각부터는 새 규칙을 적용한다.
- Edge: 유효기간이 겹치는 동일 상품 버전 — 저장을 차단하고 충돌 버전을 표시한다.
- Edge: 필수 계산값 또는 공식 출처가 없음 — 활성 상태로 저장할 수 없다.
- 규칙: 시스템은 이미 사용된 규칙 버전을 덮어쓰지 않고 새 버전으로 이력화해야 한다(MUST).

**FR-029** 운영자로서 운영 데이터 변경 이력을 확인하고 싶다, 변경 책임과 결과 적용 시점을 추적하기 위해.
- FR-029.AC1: Given 운영 데이터 변경 완료, When 감사 기록이 생성되면, Then 수행 운영자·행위·대상·변경 전후 값·변경 시각·요청 식별값이 기록된다.
- FR-029.AC2: Given 감사 기록 화면, When 기간·운영자·대상 유형·행위로 검색하면, Then 조건에 일치하는 기록이 최신순으로 표시된다.
- Edge: 데이터 저장은 성공했으나 감사 기록 생성이 실패함 — 전체 변경을 실패 처리하고 기존 값을 유지한다.
- 규칙: 시스템은 운영자가 감사 기록을 수정하거나 삭제할 수 없게 해야 한다(MUST).

## 운영자 인증 및 계정 관리

백오피스 접근을 추가 인증이 완료된 운영자에게만 허용하고 계정·세션 수명주기를 감사 가능하게 관리한다.

**FR-030** 운영자로서 이메일·비밀번호와 추가 인증으로 로그인하고 싶다, 백오피스에 안전하게 접근하기 위해.
- FR-030.AC1: Given 활성 운영자 계정, When 검증된 이메일과 올바른 비밀번호를 제출하면, Then 추가 인증 입력 단계가 표시되고 관리 데이터는 아직 노출되지 않는다.
- FR-030.AC2: Given 기본 자격 증명 검증 완료, When 등록된 추가 인증 수단의 유효한 값을 제출하면, Then 운영자 세션이 생성되고 백오피스 접근이 허용된다.
- FR-030.AC3: Given 잘못된 이메일·비밀번호·추가 인증값, When 인증이 실패하면, Then 계정 존재 여부를 구분하지 않는 동일한 오류 메시지가 표시되고 실패가 감사 기록에 남는다.
- Edge: 인증 실패가 반복됨 — 점진적 시도 제한과 추가 검증을 적용한다.
- 규칙: 시스템은 추가 인증이 완료되기 전에 ROLE-운영자 권한을 부여해서는 안 된다(MUST).

**FR-031** 운영자로서 안전한 비밀번호를 설정하고 싶다, 탈취 가능성이 높은 자격 증명 사용을 방지하기 위해.
- FR-031.AC1: Given 비밀번호 설정 또는 변경, When 12자 미만이거나 현재 사용 중인 비밀번호를 제출하면, Then 저장이 차단되고 정책 위반 사유가 표시된다.
- FR-031.AC2: Given 유출된 것으로 확인된 비밀번호, When 설정을 시도하면, Then 해당 비밀번호를 저장하지 않고 다른 비밀번호를 요구한다.
- FR-031.AC3: Given 비밀번호 변경 완료, When 이후 기존 세션으로 요청하면, Then 모든 기존 세션이 무효화되어 재로그인이 요구된다.
- Edge: 비밀번호 확인값이 일치하지 않음 — 변경을 수행하지 않는다.
- 규칙: 시스템은 비밀번호 원문을 화면·로그·감사 기록에 저장하거나 재표시해서는 안 된다(MUST).

**FR-032** 운영자로서 만료 기준이 적용되는 세션을 사용하고 싶다, 방치되거나 장시간 유지된 인증을 차단하기 위해.
- FR-032.AC1: Given 유효한 운영자 세션, When 30분 동안 활동이 없으면, Then 세션이 만료되고 다음 요청에서 재인증을 요구한다.
- FR-032.AC2: Given 인증 후 12시간이 경과함, When 운영자가 계속 활동 중이더라도, Then 세션을 만료하고 재인증을 요구한다.
- FR-032.AC3: Given 운영자 로그아웃, When 처리가 완료되면, Then 현재 세션이 즉시 무효화된다.
- Edge: 만료와 데이터 저장 요청이 동시에 발생함 — 저장을 수행하지 않고 재인증을 요구한다.
- 규칙: 시스템은 세션 활동 및 만료 여부를 신뢰할 수 있는 서버 측 시각으로 판정해야 한다(MUST).

**FR-033** 운영자로서 이메일 초대로 추가 운영자 계정을 발급하고 싶다, 공개 가입 없이 관리 인원을 추가하기 위해.
- FR-033.AC1: Given 인증된 활성 운영자, When 미등록 이메일로 초대를 발급하면, Then 지정 이메일에 귀속된 일회성 초대 링크가 생성되고 24시간 후 만료된다.
- FR-033.AC2: Given 유효한 미사용 초대, When 지정 이메일 검증·비밀번호 설정·추가 인증 수단 등록을 완료하면, Then 운영자 계정이 활성화되고 초대가 사용 완료 처리된다.
- FR-033.AC3: Given 만료되거나 취소되거나 사용된 초대, When 수락을 시도하면, Then 계정을 생성하지 않고 새 초대가 필요하다고 표시한다.
- Edge: 동일 이메일의 활성 계정 또는 유효한 초대가 존재함 — 중복 초대 발급을 차단한다.
- 규칙: 시스템은 공개 운영자 가입이나 클라이언트의 역할 신청으로 운영자 계정을 생성해서는 안 된다(MUST).

**FR-034** 운영자로서 다른 운영자 계정을 비활성화하거나 재활성화하고 싶다, 백오피스 접근 권한을 관리하기 위해.
- FR-034.AC1: Given 둘 이상의 활성 운영자 계정, When 다른 계정을 비활성화하면, Then 해당 계정의 모든 세션과 미사용 초대가 즉시 무효화된다.
- FR-034.AC2: Given 비활성 운영자 계정, When 활성 운영자가 재활성화하면, Then 해당 계정은 다음 로그인부터 인증을 다시 완료한 후 접근할 수 있다.
- FR-034.AC3: Given 마지막 활성 운영자 계정, When 비활성화를 시도하면, Then 요청이 거부되고 마지막 계정 보호 사유가 표시된다.
- Edge: 운영자가 자기 계정을 비활성화하려 함 — 다른 활성 운영자가 처리하도록 요청을 거부한다.
- 규칙: 시스템은 계정 비활성화·재활성화와 세션 무효화를 감사 기록으로 남겨야 한다(MUST).

**FR-035** 운영자로서 이메일 링크로 비밀번호를 재설정하고 싶다, 기존 비밀번호를 잊어도 계정 접근을 복구하기 위해.
- FR-035.AC1: Given 운영자 로그인 화면, When 비밀번호 재설정을 요청하면, Then 계정 존재 여부와 무관하게 동일한 완료 메시지가 표시되고 등록된 활성 계정에만 일회성·만료형 링크가 발송된다.
- FR-035.AC2: Given 유효한 재설정 링크, When 정책을 충족하는 새 비밀번호를 설정하면, Then 링크가 사용 완료 처리되고 해당 계정의 모든 세션이 무효화된다.
- FR-035.AC3: Given 만료되거나 사용된 링크, When 재설정을 시도하면, Then 비밀번호를 변경하지 않고 새 요청 수단을 표시한다.
- Edge: 재설정 완료 전 계정이 비활성화됨 — 링크를 무효화한다.
- 규칙: 시스템은 재설정 링크를 지정된 운영자 이메일에만 전달해야 한다(MUST).

**FR-036** 운영자로서 최초 로그인에서 초기 자격 증명을 교체하고 싶다, 배포 시 발급된 계정을 정상 운영 상태로 전환하기 위해.
- FR-036.AC1: Given 시드 방식으로 생성된 최초 운영자 계정, When 처음 로그인하면, Then 초기 비밀번호 변경과 추가 인증 수단 등록 화면만 접근할 수 있다.
- FR-036.AC2: Given 초기 비밀번호 변경과 추가 인증 등록 완료, When 추가 인증을 검증하면, Then 계정 초기화 상태가 해제되고 백오피스 관리 기능이 허용된다.
- Edge: 초기 설정 도중 세션이 만료됨 — 완료되지 않은 설정을 권한 부여로 인정하지 않고 처음부터 재인증을 요구한다.
- 규칙: 시스템은 최초 운영자 이메일과 초기 자격 증명을 소스 코드·배포 산출물·기본 설정값에 포함해서는 안 된다(MUST).

**FR-037** 시스템으로서 요청 역할과 백오피스 권한을 서버 측에서 검증하고 싶다, 역할 위조와 관리 데이터 노출을 차단하기 위해.
- FR-037.AC1: Given 운영자 세션이 없는 요청, When 백오피스 URL 또는 관리 기능에 접근하면, Then 관리 데이터를 반환하지 않고 운영자 로그인 화면 또는 접근 거부 상태를 제공한다.
- FR-037.AC2: Given 클라이언트 입력에 `운영자` 역할명이 포함됨, When 관리 기능을 요청하면, Then 해당 입력을 무시하고 검증된 서버 측 인증 상태만으로 권한을 판정한다.
- FR-037.AC3: Given 만료·무효화된 운영자 세션, When 관리 요청을 보내면, Then 요청을 거부하고 재인증을 요구한다.
- Edge: 고객용 URL과 백오피스 URL이 유사함 — 경로 이름이 아니라 인증된 역할과 권한 정책으로 접근을 판정한다.
- 규칙: 시스템은 하나의 요청에 검증된 단일 역할만 적용하고 역할 간 권한을 암묵적으로 상속해서는 안 된다(MUST).
